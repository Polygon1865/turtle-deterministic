# HTML 站点结构评审与改造建议

- 日期：2026-10-29
- 对象：`site/releases/2026-10-28-2`（当前 `site/current` 指向它）与生成器 `src/turtlefw/site.py`、模板 `src/turtlefw/report/templates/site_index.html.j2`
- 方法：读生成器与模板 + 对已发布 HTML 做只读探测（`tmp/site_probe*.py`）+ 参考成熟站点公开页面
- 范围：只评审结构与信息架构，不改代码、不改数据口径

---

## 0. 一句话结论

现在的站点不是「一个网站」，而是「一份首页 + 40 份报告 + 250 个按天复制的页面」被放在同一个目录里：**首页用三张互相重叠的列表讲同一批股票，详情页是另一套设计、另一套导航，所有链接都指向按日期复制的副本，同一只股票每天换一个地址。** 用户看到的「迷惑」不是视觉问题，是**页面职责没有分开**。

五个判断：

1. **首页承担了三个页面**（概览 / 筛选结果 / 报告索引），三个列表重复、口径不同。
2. **个股没有稳定身份**：`archive/2026-10-28/06110.HK.html`、`archive/2026-10-27/06110.HK.html`、`06110.HK.html` 是三个互不相关的 URL。
3. **列表页与实体页之间没有层级**：40 份报告既是「列表项」又是「全文页」，没有从列表到个股、从个股到全文的递进。
4. **导航在讲内部实现**：顶部是「候选 CSV / 深度 CSV / 健康检查」，没有「筛选 / 存档 / 方法」。
5. **每天整站复刻一次**：34 个 release、3313 个文件、171MB，单 release 250 个 HTML、16MB，其中 80% 是历史副本。

### 1.4 生成与发布

`src/turtlefw/site.py`：

- `build_site(day_dir, site_root)` 每次发布都新建 `site/releases/<label>`，**合并历史 release**，为每个日期重新渲染 `day/<key>/index.html`，把当天 40 份报告 HTML 复制到 `release/<code>.html` 与 `archive/<day>/<code>.html` 两处。
- 根 `index.html` 渲染最新日期，日期页签链接到 `day/<date>/index.html`。
- `publish_site()` 最后把 `site/current` junction 指向新 release。

## 2. 十个让人迷惑的结构问题

### 2.1 三个列表在讲同一批股票，排序口径却有三套

同一只股票会同时出现在「今日优先看」「今日报告」「候选池」里，最多出现 3 次；三处排名分别是「深度排名」「市场排名」「全局 rank」，数字对不上。用户无法判断哪一个是主视图。

**证据**：首页 3 张卡 + 40 行报告表 + 200 行候选表；`site_data.json` 里同一 code 在三处分别带 `rank` / `market_rank` / 候选 `rank`。

**影响**：首页没有「主表」，注意力被摊平；「优先看」只有 3 个且全是 A 股（按深度排名），港股 20 份报告永远上不了头条。

### 2.2 候选池把 A 股与港股塞进同一张表，列语义不同

A 股 `ranking.csv` 12 列（有 `channel`、`roe`、`payout`，**没有 PE/PB**）；港股 `ranking_hk.csv` 28 列（有 `pe`/`pb`/`currency`/`payout_ok`，没有通道）。渲染成一张 11 列表后：

- A 股 100 行的 PE / PB **全部为空**（`site_data.json` 里 100/100 行 `pe == ""`、`pb == ""`），港股 100 行全部有值；
- 「通道」列对 A 股是 `main`，对港股是常量 `HK`；
- 「结论」列：A 股 70 行为空（未深度）、30 行是深度结论（排除 27 / 观察 2 / 买入 1）；港股 100 行全部显示「观察」，与深度结论无关；
- 排序「按排名」用全局 rank，显示却是 `market_rank`（市场内名次）。

**影响**：同一列在不同行里含义不同，是「看着乱」的最大来源之一。

### 2.3 主表列的是运维指标，不是决策指标

「今日 40 份报告」的列是：QA、研究（LLM/回退/确定性）、PDF 有无、覆盖率、安全边际。这些是**生产质量信号**，不是投资决策信号；真正决定「要不要看」的结论、R/GG、底价、溢价只在 3 张卡里出现。

**影响**：用户扫完主表只得到「系统跑得不错」，得不到「今天该看谁」。

### 2.4 日期与市场两个筛选维度平铺，且不统一进 URL

6 个日期页签 + 3 个市场页签同时出现；日期在路径里，市场只在内存里（读 `?market=` 但不写回）。从 10-28 切到 10-27 会丢掉「只看港股」。

**影响**：两个维度互相打断；分享出去的是「某天的全部」，不是「某天的港股」。

### 2.5 同一个模板，两种身份

根 `index.html` 的 h1 是「今日研究终端」，`day/<date>/index.html` 的 h1 是「YYYY-MM-DD 研究存档」，但两者正文结构、统计数字、表格完全一样。

**影响**：用户以为「存档页」是另一种东西，其实只是同一页换了标题。

### 2.6 详情页是「另一个站点」

首页 header：品牌 + 三个 CSV 链接；详情页 header：品牌 + 返回链接；两套 CSS、两套字体、两套布局。从首页点进报告，视觉与导航都断掉，且详情页**没有搜索、没有市场入口、没有存档入口**。

**影响**：阅读报告时无法回到筛选结果，也无法看同一天其他股票（只能返回再找）。

### 2.7 链接指向按日副本，根目录同名副本无人引用

首页 48 个链接指向 `archive/<date>/...`、5 个指向 `day/<date>/...`；根目录同时存在 40 份 `<code>.html`（与 archive 内容相同），**没有任何页面链接它们**。

**影响**：两套 URL 并列，外部分享与搜索引擎会分裂；昨天 `/06110.HK.html` 能打开，今天首页链接却是 `/archive/2026-10-28/06110.HK.html`——同一个东西两个地址。

### 2.8 个股没有稳定身份，跨日无法连起来

`archive/2026-10-27/06110.HK.html` 与 `archive/2026-10-28/06110.HK.html` 是两个互不相关的页面，没有「上一份 / 下一份 / 历史结论」链接；同一只股票的结论变化只能靠人肉翻日期。

**影响**：站点无法回答「这只票过去一周结论怎么变的」，而这恰恰是日报类产品最有价值的信息。

### 2.9 归档 = 每天整站复刻

每个 release 都包含全部历史日期的页面：41 个根页面 + 203 个归档报告 + 6 个日索引 = 250 个 HTML。34 个 release 累计 171MB、3313 个文件。

**影响**：磁盘与构建时间线性增长；每次发布都要重写历史页面，任何一次渲染改动都会让所有历史页面「看起来也变了」。

### 2.10 细节缺陷（顺手可修）

- 模板第 173 行 `</style></style>` 重复闭合（`site_index.html.j2:173`）。
- 顶部导航只有 `ranking.csv` / `ranking_deep.csv` / `health.txt`，`ranking_hk.csv` 只出现在页脚。
- 无 favicon、无 OG/Twitter 卡片、无 canonical、无 sitemap。
- 移动端 `topbar nav { display: none }`，导航直接消失。
- 全站无图表：没有价格走势、没有财务趋势、没有估值分位。
- 首页 193KB 全量内联（CSS + 200 行表格 + 40 行表格），没有缓存分层。

## 3. 成熟站点怎么组织

### 3.1 三个可参照的样本

| 站点 | 结构 | 值得借鉴 | 不适用之处 |
|---|---|---|---|
| **Finviz** | 全局导航（Screener / Maps / News / Groups / Insider / **Watchlist** / Portfolio / Calendar）；Screener 是核心产品面，同一结果集提供 Overview / Snapshot / Fundamental / Financial / Ownership / Performance / Technical 多视图，列可切换；每一行都链到独立的 Stock Overview；筛选组合可保存为 preset；支持 CSV 导出 | ①「筛选器」是一个独立页面而不是首页的一段；②同一批数据用**列组/视图**切换，而不是把所有列堆在一张表；③每行是入口，不是全文；④预设与导出是筛选器的标配 | 它是交易导向、密度极高、没有「日报」叙事，不能照抄密度 |
| **Finviz 个股页** | 报价头（Last Close + 涨跌）→ 页签 Overview / Compare / Short Interest / Financials / Options / Filings / Dilution → 行业/指数/同行链接 → 两张密集指标表 | ①个股页第一屏是「报价 + 结论性数据」；②页签按**问题**分（估值/财务/事件），不按数据源分；③同行与指数是横向导航 | 偏行情，不覆盖基本面研究叙事 |
| **Screener.in** | 每个公司一个固定 URL（`/company/RELIANCE/`），页内锚点导航 11 节：Summary / Chart / Analysis / Peers / Quarters / P&L / Balance Sheet / Cash Flow / Ratios / Investors / Documents；顶部关键比率条（市值/价格/PE/ROE/ROCE…）可自定义；Pros/Cons 摘要；Follow 与导出 | ①**一个实体一个 URL**；②长页面用锚点导航而不是分页；③摘要区先给结论性比率与优缺点；④同行比较内嵌在同一页 | 单页极长（10 年数据），需要更强的折叠策略 |
| **Yahoo Finance / 雪球（常识对照）** | 报价头 + 页签（Summary / Statistics / Financials / Holders / History / Profile；中文站常见 行情 / 财务 / 公告 / 讨论） | ①页签数量少（5–8 个），每个页签回答一类问题；②报价头常驻；③自选/组合是独立一级入口 | 需要账户体系与实时行情，当前静态站不具备 |

参考链接：
- Finviz Screener 帮助：https://charts2.finviz.com/help/screener
- Finviz 个股页：https://finviz.com/stock?t=AAPL
- Screener.in 公司页：https://www.screener.in/company/RELIANCE/consolidated/
- Yahoo Finance 个股页：https://finance.yahoo.com/quote/AAPL/

### 3.2 抽出来的六条通用规律

1. **一个实体一个 URL**：股票、筛选视图、页面类型都有稳定地址；日期与筛选条件是参数，不是路径身份。
2. **列表页 ≠ 实体页**：列表只回答「有谁、排第几、为什么在列」，实体页回答「它怎么样」。
3. **一级导航回答用户任务**（找股票 / 筛股票 / 看历史 / 懂方法），不暴露内部文件。
4. **决策信息在上，质量/元数据在下**：结论、估值、安全边际先给；QA、覆盖率、数据源是次级信息。
5. **历史是「时间轴」不是「目录」**：同一实体跨日可对比；日期是 as-of 参数。
6. **视图可切换**：同一批数据允许「决策视图 / 质量视图 / 估值视图」，而不是一张万能表。

## 4. 目标信息架构

### 4.1 页面树与 URL

```
/                              首页：今日概览（结论 + 变化 + 入口）
/screener.html                 筛选器：A 股 / 港股 两个独立视图
/stock/<code>.html             个股页：默认最新快照
/stock/<code>.html?asof=2026-10-27   个股页：历史快照
/report/<code>.html            报告全文（个股页的“报告”页签也可直接打开）
/archive/                      存档索引：按月分组
/archive/<date>/               当日快照（旧 day/<date>/ 保留并 301/跳转）
/method.html                   方法、指标定义、数据口径与限制
/data/                         数据下载（ranking*.csv、health、site_data.json）
```

兼容旧链接：保留 `archive/<date>/<code>.html` 作为真实页面，但在 `<head>` 加 `canonical` 指向 `/stock/<code>.html?asof=<date>`；根目录的 40 份副本要么删掉，要么做成指向 `archive/...` 的跳转页。

### 4.2 一级导航

`首页 · 筛选 · 存档 · 方法`（右上角：数据下载、健康状态）。当前日期与数据日放在页头一行，不占导航位。

### 4.3 每页的职责

| 页面 | 回答的问题 | 不该出现的内容 |
|---|---|---|
| 首页 | 今天发生了什么？最值得看哪几只？去哪深入？ | 200 行全量候选表、CSV 链接、QA 细节 |
| 筛选器 | 全市场满足条件的有谁？按什么排序？ | 报告摘要、LLM 叙事 |
| 个股页 | 这只票结论是什么？证据是什么？历史怎么变？ | 其他股票的列表 |
| 存档 | 某一天的全貌是什么？ | 当日全部报告正文（只给列表与入口） |
| 方法 | 这些指标怎么算？口径与限制是什么？ | 个股数据 |

### 4.4 内容迁移表

| 现在的位置 | 建议去向 |
|---|---|
| 「今日优先看」3 张卡 | 首页保留，扩到 5 张，A/HK 各至少 1 张，并标注「入选理由」（边际最高 / 结论变化 / 新进榜） |
| 「今日 40 份报告」表 | 首页保留但**换列**：结论 / R% / GG% / 安全边际 / 底价 / 溢价 / 市场；QA、覆盖率、PDF 折叠为「质量」次级列或移到个股页 |
| 「候选池 200」表 | 移到 `/screener.html`，按市场拆成两个视图，列组可切换 |
| 日期页签 | 移到页头「数据日选择器」（下拉/日历），同时进 URL |
| CSV / health 链接 | 移到 `/data/` 与页脚 |
| 详情页 TOC + 面板页签 | 保留，但嵌进统一站点外壳；个股页的「报告」页签直接复用 |
| 根目录报告副本 | 删除或改为 canonical 跳转 |

## 6. 生成器层面的改造（site.py）

1. **拆页面生成器**：`layout.py`（外壳/导航/OG/canonical）+ `home.py` + `screener.py` + `stock.py` + `archive.py`，共用同一套 CSS tokens；报告页通过后处理注入外壳（或在 `html.py` 输出时传入 layout），不再各写一套 header。
2. **稳定 URL + 历史参数**：个股页从「按日复制」改为「按代码生成一次 + `?asof=` 读取快照」；`site_data.json` 增加 `history: {code: [{date, verdict, margin, r, gg}]}`。
3. **归档不再整站复刻**：release 目录只写当日增量（`archive/<date>/` 只存当日报告），历史页面引用既有目录；`current` 仍用 junction。目标：单日新增 < 2MB，而不是 15MB。
4. **统一候选模型**：`Candidate` 用可空字段（`channel`、`pe`、`pb`、`currency`、`payout_ok`），A/HK 各一套列定义；渲染时按市场取列集，避免空列。
5. **首页 diff**：与上一交易日对比，计算新进/移出/结论变化，写进 `site_data.json` 的 `diff`，首页直接展示。
6. **链接与元数据**：每页 `<link rel="canonical">`、OG title/description、favicon、`sitemap.xml`；旧路径保留但加 canonical。
7. **筛选状态进 URL**：`?market=HK&sort=margin&min_margin=5&channel=main`，页面加载时读回并高亮控件；市场切换用 `history.replaceState`。
8. **报告页统一外壳**：报告 HTML 的 header 由 `_copy_report_html` 注入站点导航（首页/筛选/存档/方法 + 返回当日），而不是只改一个返回链接。

## 7. 分阶段实施

### P0（结构纠偏，1–2 天）

1. 首页拆三段：保留「今日概览」+「今日报告（决策列）」+「入口」，把候选池表移到新 `/screener.html`。
2. 报告表换列：结论、R%、GG%、边际、底价、溢价在前；QA/覆盖率/研究/PDF 收进「质量」次级视图。
3. 市场切换写入 URL（`?market=HK`），日期切换保留 market 参数；市场页签与日期页签视觉上降级为「数据日」一行。
4. 候选表按市场拆成两个表（或两个 tab），A 股不再渲染 PE/PB 空列。
5. 修 `</style></style>`、补 favicon/OG/canonical；页脚统一放 CSV/health。
6. 删除根目录 40 份孤儿报告副本，或改为 canonical 跳转。

### P1（个股页与存档，3–5 天）

1. `/stock/<code>.html`：统一外壳 + 决策头 + 页签（决策/财务/研究/报告/历史）。
2. `/stock/<code>.html?asof=` 与「历史结论」时间线；`site_data.json` 增加 history。
3. `/archive/` 索引页，按月分组，显示每日报告数/通过率/结论分布。
4. 首页「今日变化」diff（新进/移出/结论变化）。
5. 报告页注入统一导航。

### P2（增强，按需）

1. 价格与财务趋势图（静态 SVG 或轻量 JS）。
2. 行业/概念聚合页（同行业横截面）。
3. 全站搜索（代码/名称，静态索引 JSON）。
4. 自选/组合（需要账户或 localStorage；当前无后端，建议先做 localStorage 版）。
5. 归档增量构建与发布体积优化（P0 之后即可做，收益最大）。

**不建议现在做**：账户体系、实时行情、复杂前端框架。当前是静态日报，先解决「页面职责」和「稳定 URL」，收益远大于技术栈升级。

## 8. 验收标准

- [ ] 首页只有一张主表，且列是决策指标（结论/R/GG/边际/底价/溢价）。
- [ ] 同一只股票在首页最多出现 1 次（卡片或表格，不重复）。
- [ ] A 股与港股不在同一张表里混排；A 股表不出现全空的 PE/PB 列。
- [ ] 任一页面 URL 只由「页面类型 + 实体 + 参数」组成，不含「第几次发布」。
- [ ] `/stock/<code>.html` 可打开，且能切换到任一历史日期。
- [ ] 从个股页可一键回到「当日列表 / 筛选器 / 首页」，不需要浏览器后退。
- [ ] 一级导航是「首页 / 筛选 / 存档 / 方法」，CSV 与 health 不在主导航。
- [ ] 单日发布新增页面 < 50，发布体积 < 5MB（当前 250 页 / 16MB）。
- [ ] `</style>` 只出现一次；每页有 canonical、OG 标题、favicon。
