# Clean-room 与 CI：设计目的、目标与边界

> 这是一份设计说明，不是让你现在拍板。先说明“为什么做、做成什么样、怎么判断有效”，具体阈值/样本/是否阻断可以后面再定。

## 1. 为什么需要 clean-room

本地已经把数字从 LLM 手里拿回来了，但仍有四类风险：

1. **同一实现错误被重复信任**：主引擎和测试都调用同一函数，单位/口径错了两边一起错。
2. **数据层错误**：Tushare 字段缺失、单位变化、报告期错位、港股 line-item 缺项。
3. **PDF 与数据源不一致**：例如 00700 的 PDF 营业收入 751,766 百万 vs Tushare 743,689 百万（差 8,077，正好是 "Others" 分部）；capex 曾只取无形资产 25,393，漏了 PPE 87,482。
4. **结论与数字脱节**：底价、仓位、verdict 被后处理改动，报告段落仍写旧值。

Clean-room 的目的不是“再找一个 LLM 点评”，而是**独立于主实现、可重复地发现上述错误**。

## 2. 设计目标

### 目标
- **独立重算**：至少用另一条代码路径重算关键数字，而不是 import 主引擎函数。
- **可追溯**：每个数字带来源（Tushare 行/PDF 页码/公式），差异输出为 JSON。
- **可解释**：差异必须能归因到单位、期间、字段、公式之一。
- **低误报**：在 20–30 个样本上先测误报率，再谈是否阻断。
- **不锚定**：clean-room 不读 `analysis_report.md`、不读草稿结论，只读原始数据/PDF。
- **可关闭**：默认建议型，失败不阻塞发布；是否升级为阻断是配置，不是一次性架构决定。

### 非目标
- 不替代人类研究判断；
- 不评价护城河/管理层等定性结论的“对错”；
- 不让 LLM 重算数字；
- 不追求和主引擎 100% 一致（一致可能是一起错）。

## 3. 两层设计

### A. Numeric clean-room（数值）
输入：
- 原始 Tushare 行（或缓存的 Parquet/JSON）；
- 年报 PDF 的 `reported_numbers.json` + `cash_bridge`；
- 版本化公式规范。

重算：
- R、GG、底价、净现金、支付率、Capex/D&A、6 项 PDF 数字；
- 用独立实现（例如直接按公式重写，或从 PDF 数字反算）；
- 对比主引擎输出，输出：
```json
{"item":"revenue","main":743689,"clean":751766,"diff_pct":1.09,
 "cause":"PDF 含 Others 分部；Tushare 未含","severity":"review"}
```

### B. Semantic clean-room（语义，可选）
输入：定性证据 JSON + PDF 章节，不读主报告。
检查：
- 证据 URL/引文是否支持 judgment；
- 是否存在“网页摘要冒充年报原文”；
- 管理层/护城河判断是否引用了正确的期间/主体；
- 结论与止损条件是否自相矛盾。

语义层只输出 `review` 建议，不自动改结论。

## 4. 建议型 vs 阻断型（先不决定）

| 模式 | 行为 | 适合阶段 |
|:--|:--|:--|
| 建议型 | 输出 `cleanroom.json`，`qa` 只提示，不阻塞 | 现在：先测误报 |
| 阻断型 | 数值差 >阈值/结论不同则禁止发布 | 样本和误报率稳定后 |

**现在不需要选**。可以先实现建议型，把 20 个样本跑一遍，用数据决定是否值得阻断。

## 5. 成功标准

- 在 20–30 个样本上，clean-room 能独立发现至少 3 类真实问题（单位/期间/字段/公式）；
- 误报率可接受（例如 <10%），每个误报都能解释；
- 同一输入重复运行结果一致；
- 差异 JSON 能被人快速定位到数据源/公式；
- 不显著增加主流程耗时（可离线/异步跑）。

## 6. CI 的设计目的

CI 和 clean-room 不是一回事：

- **CI 防回归**：代码改动不能弄坏已通过的测试/类型/确定性输出。
- **CI 不证明分析正确**：测试通过 ≠ 估值正确；正确性要靠 clean-room + 人工样本。
- **live smoke 单独跑**：真实 Tushare/yfinance 有网络、限频、token 权限，不能放在每个 PR 的必过门里。

### 分三层
1. **PR 离线门（已加）**：`pytest` + 核心模块 `mypy`，不需要 token。
2. **Nightly live smoke（待接）**：1–3 只股票，真实取数 + 生成报告，失败只告警。
3. **Release golden（待建）**：固定快照 + 人工标注，比较 verdict/关键数字，不依赖实时数据。

### CI 非目标
- 不评价投资建议好坏；
- 不把 LLM 输出当断言；
- 不在 CI 里跑长时间全市场筛选。

## 8. 结论

Clean-room 的价值是**独立发现数字/口径错误**，不是“多一个 AI 意见”；CI 的价值是**防回归**，不是“证明分析正确”。

因此现在不必决定“建议型还是阻断型”“样本用哪些”“阈值多少”。先把建议型跑起来、积累差异样本，再让数据决定是否升级。
